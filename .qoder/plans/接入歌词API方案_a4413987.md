## 二、实现方案 - 混合模式(本地+API)

### 方案A: 自建LrcApi(推荐)

**优点:** 稳定、可控、响应快、无限制  
**缺点:** 需要额外部署服务(Docker或Python)

**集成步骤:**
1. 后端部署LrcApi服务(Docker方式最简单)
2. 前端封装API调用层
3. 支持根据歌曲信息自动匹配歌词

### 方案B: 使用公开的第三方API

**优点:** 无需部署,即用即走  
**缺点:** 可能有访问限制、稳定性不可控

**可选API:**
- LrcApi公开服务: `https://api.lrc.cx/lyrics`
- 网易云音乐API(非官方)
- QQ音乐API(非官方)

### 方案C: 混合方案(最终推荐)

**策略:**
1. 本地文件优先: 有.lrc文件直接使用
2. API自动获取: 无本地歌词时自动调用API
3. 降级处理: API失败时显示"暂无歌词"

```

├── api/
```

### 3.2 核心功能实现

#### 1. API配置层 `src/config/apiConfig.ts`
```typescript
export const API_CONFIG = {
  lyricSources: [
    { name: 'LrcApi', baseUrl: 'https://api.lrc.cx', enabled: true },
    // 预留更多源
  ],
  timeout: 5000,
  retryCount: 2
}
```

#### 2. API封装层 `src/api/lyricApi.ts`
功能:
- `searchLyric(artist, title)` - 搜索歌词
- `getCover(artist, title)` - 获取封面
- 错误处理和重试机制
- 超时控制

#### 3. Hook层 `src/hooks/useLyricFetch.ts`
智能获取策略:
- 优先检查本地是否有对应.lrc文件
- 无本地文件时调用API
- 返回状态: loading/success/error
- 自动缓存API结果

### 3.3 用户交互流程

```
场景1: 导入本地音乐文件
→ 同时导入.lrc → 使用本地歌词
→ 无.lrc → 自动调用API获取 → 显示歌词 / 显示"暂无歌词"

场景2: 播放歌曲切换
→ 检查是否有歌词缓存
→ 无缓存 → 调用API获取
→ 更新歌词显示

场景3: 手动刷新歌词(新增按钮)
→ 重新调用API
→ 覆盖现有歌词
```

## 四、技术要点

### 4.1 API调用安全
- 使用 `fetch` + `AbortController` 支持请求取消
- 超时控制(5秒)
- 错误边界处理

### 4.2 性能优化
- 歌词结果缓存(避免重复请求)
- 使用 `localStorage` 持久化API歌词
- 防抖处理(避免快速切歌时重复请求)

### 4.3 兼容性
- 保持现有所有功能不变
- API失败时降级到"暂无歌词"状态
- 支持用户手动导入覆盖API歌词

## 七、验收标准

| 功能 | 验收标准 |
|------|---------|
| 本地歌词 | 导入.lrc文件,正常显示滚动歌词 |
| API歌词 | 无本地歌词时,自动调用API并显示 |
| 降级处理 | API失败时,显示"暂无歌词",不影响播放 |
| 性能 | API响应 <3秒,有缓存时<100ms |
| 兼容性 | 不破坏现有任何功能 |

---

## 八、风险评估

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| API不稳定 | 歌词获取失败 | 多源降级、本地缓存 |
| 跨域限制 | 浏览器无法访问API | 配置CORS或使用代理 |
| 歌词匹配不准 | 显示错误歌词 | 允许用户手动替换 |
| 公开API限流 | 高频使用受限 | 添加请求缓存和防抖 |
